### Revisión autónoma 1 (2026-11-13) — Requiere cambios
**Críticos**
Ninguno.

**Importantes**
1. `frontend/src/app/features/catalog/categories/categories.service.ts:19-26`, `brands/brands.service.ts:20-27`, `taxes/taxes.service.ts:17-24` y `scale/scale.service.ts:17-24` — Los cuatro servicios desempaquetan respuestas exitosas `Blob` mediante `unwrapBody`, pero no desempaquetan el `ProblemDetail` cuando el servidor responde 4xx/5xx con `responseType: 'blob'`. Con `errorInterceptor` activo en `app.config.ts`, los cuatro diálogos (`CategoryFormDialog`, `BrandFormDialog`, `TaxFormDialog`, `ScaleFormDialog`) pasan `withoutErrorNotification()` y dependen de `err.hasFieldErrors` y `err.message`, pero recibirán `ApiError` con `code: 'UNKNOWN_ERROR'`, `message: 'Error HTTP <status>'` y `errors: []`. Esto oculta errores por campo (`VALIDATION_ERROR`), duplicados o conflictos (`ENTITY_IN_USE` al desactivar categoría, vigencia superpuesta en impuestos o prefijo duplicado en balanza). — **Corrección:** añadir el manejo `unwrapApiError()` (leyendo `err.cause.error` cuando `isApiError(err) && err.cause instanceof HttpErrorResponse` y `error instanceof Blob`, parseando JSON y relanzando `ApiError.fromHttpError(...)`, equivalente al patrón de `T34` en `settings-api.utils.ts`) en todos los métodos de los cuatro servicios (incluyendo `deactivate*`/`activate*`), y añadir cobertura con `errorInterceptor` + error `Blob` en los specs de servicio.

**Menores**
1. `frontend/src/app/features/catalog/{categories,brands,taxes,scale}/*.service.ts` — `unwrapBody` (y próximamente `unwrapApiError`) se repite en los cuatro servicios por la separación de carpetas permitidas (`features/catalog/{categories,brands,taxes,scale}/**`); cuando se consolide un helper común en `core/`, convendrá unificarlo.
2. Verificación global de revisión (en `frontend/`): `npm run format:check` OK, `npm run lint` OK, `npm test -- --watch=false` OK (**35 archivos / 363 pruebas**), `npm run build` OK (`639.42 kB`, warning preexistente de budget de `500.00 kB`).
