**Menores**
1. `backend/src/main/java/cl/minimarket/pos/sales/application/returns/SaleReturnService.java:829-881` — `PaymentGateway.refund` se invoca dentro de la transacción que ya aplicó el reingreso de stock; A.5 pide que las llamadas externas nunca ocurran dentro de una transacción que bloquea stock. Con el gateway simulado (instantáneo) el impacto es nulo, pero un proveedor real exigiría rediseñarlo (reversa en paso previo o post-commit con estado pendiente). — Registrar la decisión para el orquestador; opcionalmente mover la reversa antes de `stockApi.apply` (no resuelve el bloqueo, pero reduce la ventana).
2. `backend/src/test/java/cl/minimarket/pos/sales/web/returns/SaleReturnControllerIT.java:199-333` — La anulación con tarjeta no afirma la evidencia directa del uso del `PaymentGateway` simulado: el reembolso DEBIT debería dejar `sale_return_refunds.gateway_reference` con prefijo `SIM-REF-`. — Agregar esa aserción (distinguiría una reversa real por gateway de una simple copia del `gateway_reference` original).
3. `backend/src/test/java/cl/minimarket/pos/sales/web/returns/SaleReturnControllerIT.java:96-196` — El caso positivo de reingreso afirma stock y lote, pero no la existencia del movimiento de kardex `SALE_RETURN` (`stock_movements` con `source_type='SALE_RETURN'`, `source_id=saleReturnId`); solo el caso negativo (merma) cuenta movimientos. — Agregar el conteo positivo (RN-02 lo garantiza junto al stock, así que es refuerzo, no hueco funcional).
4. `backend/src/main/java/cl/minimarket/pos/sales/application/returns/SaleReturnJdbcRepository.java:171-173` — `lockSaleLines` es código muerto: el servicio usa `findSaleLines` y el bloqueo de la venta (`lockSale` con `FOR UPDATE`) ya serializa los escritores concurrentes, suficiente para RN-13 según F.4 ("se bloquea la venta"). — Eliminarlo o usarlo (si se prefiere bloquear también las líneas).
5. `backend/src/test/java/cl/minimarket/pos/sales/application/returns/SaleReturnServiceTest.java:98` — El test stubbe `lockSaleLines(50L)`, que el servicio nunca invoca (usa `findSaleLines`), así que el fixture de líneas queda muerto; el test pasa igual porque su objetivo (`PAYMENT_DECLINED` al rechazar la reversa) no depende de las líneas. — Stubbear `findSaleLines` (o borrar el stub) al tocar el archivo por cualquier otro motivo.
